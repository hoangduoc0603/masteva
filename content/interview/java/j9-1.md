# j9.1 · File với NIO.2, charset và UTF-8

Nguồn cho bộ câu hỏi phỏng vấn, chép nguyên văn từ phần Đào sâu khi chuyển bài lab sang bài đọc. Chưa hiển thị trên trang. Định dạng: `docs/content-standard.md` §3.7.

## Mojibake đã lỡ lưu vào database thì cứu thế nào?

Nếu chuỗi hỏng được tạo bằng cách giải mã UTF-8 theo windows-1252, làm ngược lại: `new String(bad.getBytes(Charset.forName("windows-1252")), StandardCharsets.UTF_8)`. Phải sửa trên một bản sao, đếm số dòng còn chứa `�` sau khi sửa, và tìm lại dữ liệu gốc cho những dòng đó.

## Tên file tiếng Việt trên macOS có vấn đề gì?

Hệ thống file của macOS có thể trả tên file ở dạng NFD, trong khi tên bạn gõ trong code là NFC. `Files.exists(Path.of("Hà Nội.csv"))` vẫn đúng vì hệ thống file so sánh không phân biệt dạng chuẩn hoá, nhưng so sánh `Path.getFileName().toString()` với một chuỗi bằng `equals` có thể sai. Chuẩn hoá cả hai vế về NFC trước khi so sánh, như bước 5.

## Khi nào vẫn dùng java.io thay vì NIO.2?

Khi API bạn gọi chỉ nhận `InputStream` hay `Reader`: thư viện parse, body của HTTP request, `System.in`, resource trong file jar (`getResourceAsStream`). `Files` cũng trả về các kiểu đó (`newInputStream`, `newBufferedReader`), nên hai thế giới ghép được với nhau. Lớp `java.io.File` thì nên tránh trong code mới; cần thì đổi qua lại bằng `file.toPath()` và `path.toFile()`.

## Files.writeString ghi được nửa chừng thì sao?

Nếu process chết giữa chừng, file đích có thể chỉ còn một nửa. Cách an toàn cho file quan trọng là ghi ra file tạm trong cùng thư mục, rồi `Files.move(tmp, target, StandardCopyOption.ATOMIC_MOVE)`. Người đọc chỉ thấy bản cũ hoặc bản mới hoàn chỉnh.

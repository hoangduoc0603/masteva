### java.io: luồng byte và luồng ký tự

Gói `java.io` có từ Java 1.0 và chia làm hai nhánh:

| Nhánh | Lớp gốc | Đơn vị | Ví dụ |
|---|---|---|---|
| Luồng byte (byte stream) | `InputStream`, `OutputStream` | `byte` | Ảnh, file zip, dữ liệu mạng thô |
| Luồng ký tự (character stream) | `Reader`, `Writer` | `char` | File văn bản, CSV, JSON |

Ổ đĩa và mạng chỉ chứa byte. Để có ký tự, bạn phải giải mã byte theo một **charset** (bảng quy ước chuyển ký tự thành byte và ngược lại). Lớp cầu nối là `InputStreamReader`. Các lớp `java.io` lồng vào nhau, mỗi lớp thêm một khả năng:

```text
file trên đĩa
   |  FileInputStream          đọc byte thô
   v
InputStreamReader(..., UTF_8)  giải mã byte -> char theo charset
   |
   v
BufferedReader                 gom vào bộ đệm, đọc từng dòng bằng readLine()
```

Đây là mẫu **decorator**: mỗi lớp bọc lớp bên trong. Đóng lớp ngoài cùng sẽ đóng cả chuỗi.

### NIO.2: Path và Files

Java 7 thêm gói `java.nio.file` (gọi là **NIO.2**). `Path` là một đường dẫn; `Files` là lớp tiện ích có method tĩnh cho hầu hết việc thường gặp:

| Việc | Method | Ghi chú |
|---|---|---|
| Đọc cả file thành chuỗi | `Files.readString(path)` | Chỉ dùng cho file nhỏ |
| Đọc từng dòng, file lớn | `Files.lines(path, cs)` | Trả `Stream<String>`, phải đóng |
| Đọc kiểu cổ điển | `Files.newBufferedReader(path, cs)` | Giống chuỗi `java.io` ở trên, gọn hơn |
| Ghi chuỗi | `Files.writeString(path, text, cs)` | Mặc định tạo mới hoặc ghi đè |
| Tạo thư mục | `Files.createDirectories(dir)` | Không lỗi nếu đã có |
| Sao chép, di chuyển | `Files.copy`, `Files.move` | Thêm `REPLACE_EXISTING` để ghi đè |
| Duyệt thư mục | `Files.list(dir)`, `Files.walk(dir)` | `walk` đi cả thư mục con; phải đóng |

So với lớp `java.io.File` cũ, `Files` ném exception có tên rõ ràng (`NoSuchFileException`, `AccessDeniedException`) thay vì trả `false`, nên bạn biết vì sao thao tác thất bại.

`Files.lines`, `list` và `walk` giữ file hoặc thư mục mở cho tới khi stream được đóng. Luôn đặt chúng trong **try-with-resources** (khối `try (...)` tự gọi `close()` khi ra khỏi khối, đã học ở J4):

```java
try (Stream<String> lines = Files.lines(file, StandardCharsets.UTF_8)) {
    lines.skip(1).forEach(System.out::println);
}
```

`IOException` là checked exception: bạn phải bắt hoặc khai báo `throws`. Bên trong lambda của stream không ném được checked exception, nên `Files.lines` bọc lỗi đọc trong `UncheckedIOException`.

<Callout kind="production">

Một job đọc log bằng `Files.readAllLines` chạy ổn nhiều tháng, tới ngày file log lên 3 GB thì JVM chết với `OutOfMemoryError`: method này nạp mọi dòng vào một `List`. Với file không biết trước kích thước, đọc từng dòng bằng `Files.lines` hoặc `BufferedReader`. Một lỗi khác hay gặp là quên đóng stream của `Files.list` trong một vòng lặp: sau vài nghìn lần, process báo `Too many open files`.

</Callout>

<Check id="j9.1.nio-api">Chọn được method `Files` phù hợp cho: đọc file cấu hình nhỏ, đọc log vài GB, duyệt cả cây thư mục; và giải thích vì sao phải đóng stream của `Files.lines`.</Check>

### Charset: ký tự thành byte

Mỗi ký tự có một **code point** trong Unicode, ví dụ `ệ` là U+1EC7. Charset quy định code point đó được ghi thành những byte nào:

| Charset | `ệ` thành | `"Việt"` | Ghi chú |
|---|---|---|---|
| UTF-8 | `e1 bb 87` (3 byte) | 6 byte | 1 byte cho ASCII, 2 đến 4 byte cho ký tự khác; chuẩn của web, Linux, JSON |
| UTF-16 | `1e c7` (2 byte) | 8 byte | Cách `String` lưu trong bộ nhớ (theo đơn vị `char`) |
| ISO-8859-1 | không có, thành `?` | 4 byte | Chỉ 256 ký tự Tây Âu |

`String.length()` đếm số `char` (đơn vị UTF-16), không phải số byte. Khi giới hạn độ dài cột database hay kích thước message, hãy đo bằng `getBytes(StandardCharsets.UTF_8).length`.

**Mojibake** (chữ hỏng do giải mã sai charset) xảy ra khi ghi bằng một charset và đọc bằng charset khác, ví dụ đọc UTF-8 bằng windows-1252 (bảng mã Tây Âu của Windows, mở rộng từ ISO-8859-1):

```text
"ễ"  --ghi UTF-8-->  e1 bb 85  --đọc bằng windows-1252-->  "á" "»" "…"  =  "á»…"
```

Không có byte nào bị mất, chỉ là bị hiểu sai. Vì vậy mojibake thường sửa ngược được, trừ khi trên đường đi có byte bị thay bằng ký tự thay thế `�`.

### Charset mặc định từ Java 18

Trước Java 18, charset mặc định lấy theo hệ điều hành: UTF-8 trên Mac và Linux, nhưng thường là windows-1252 trên Windows. Cùng một chương trình đọc file tiếng Việt đúng trên Mac và hỏng trên Windows. **JEP 400** (Java 18) đổi charset mặc định của API thành UTF-8 trên mọi nền tảng. Các method của `Files` thì luôn dùng UTF-8 khi bạn không truyền charset.

Còn hai chỗ vẫn phụ thuộc môi trường:

- `System.out` và `System.err` mã hoá theo `stdout.encoding`, lấy từ locale của terminal. Trong container không đặt `LANG`, giá trị này là ASCII và mọi ký tự có dấu thành `?`.
- File do hệ thống khác tạo ra có thể không phải UTF-8: phần mềm bán hàng cũ trên Windows hay xuất file windows-1258 (bảng mã tiếng Việt của Windows).

Quy tắc của bài: **luôn truyền `StandardCharsets.UTF_8` tường minh** khi đọc ghi file và mạng. Code nói rõ ý định, và không đổi hành vi khi chạy trên máy khác.

### 4. Tổng hợp doanh thu bằng NIO.2

Chương trình duyệt thư mục `data` bằng `Files.walk`, đọc mọi file `.csv` bằng `Files.lines`, ghi báo cáo bằng `Files.writeString` và sao lưu file gốc bằng `Files.copy`.

<Terminal where="mac" title="src/ReportOrders.java">

```bash
cd ~/masteva-j9
cat > src/ReportOrders.java <<'EOF'
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.nio.file.Files;
import java.nio.file.NoSuchFileException;
import java.nio.file.Path;
import java.nio.file.StandardCopyOption;
import java.util.List;
import java.util.Map;
import java.util.TreeMap;
import java.util.stream.Stream;

public class ReportOrders {
    public static void main(String[] args) throws IOException {
        Path dataDir = Path.of(args.length > 0 ? args[0] : "data");
        Path outDir = Path.of("out");
        try {
            List<Path> files;
            try (Stream<Path> paths = Files.walk(dataDir)) {
                files = paths.filter(p -> p.toString().endsWith(".csv")).sorted().toList();
            }
            Map<String, Long> totals = new TreeMap<>();
            for (Path file : files) {
                try (Stream<String> lines = Files.lines(file, StandardCharsets.UTF_8)) {
                    lines.skip(1)
                         .filter(line -> !line.isBlank())
                         .map(line -> line.split(","))
                         .forEach(cols -> totals.merge(cols[1], Long.parseLong(cols[3]), Long::sum));
                }
                System.out.println("Đã đọc " + file + " (" + Files.size(file) + " byte)");
            }
            StringBuilder report = new StringBuilder();
            totals.forEach((customer, total) -> report.append(customer).append(": ").append(total).append('\n'));

            Files.createDirectories(outDir.resolve("backup"));
            Path output = outDir.resolve("report.txt");
            Files.writeString(output, report, StandardCharsets.UTF_8);
            for (Path file : files) {
                Files.copy(file, outDir.resolve("backup").resolve(file.getFileName()),
                        StandardCopyOption.REPLACE_EXISTING);
            }
            System.out.println("Đã ghi " + output + " (" + Files.size(output) + " byte)");
        } catch (NoSuchFileException e) {
            System.err.println("Không tìm thấy: " + e.getFile());
            System.exit(2);
        }
    }
}
EOF
java src/ReportOrders.java && cat out/report.txt && ls out/backup
```

### Khi gặp lỗi

<Callout kind="pitfall">

- `MalformedInputException: Input length = 1`: file không phải UTF-8. Hỏi nguồn xuất file dùng bảng mã gì, rồi đọc bằng đúng charset đó hoặc chuyển sang UTF-8 bằng `iconv`. Đừng đổi sang ISO-8859-1 chỉ để hết lỗi: chương trình chạy, nhưng dữ liệu thành mojibake.
- Dòng tiêu đề thành `﻿code`: file CSV lưu từ Excel bằng "CSV UTF-8" có thêm BOM (ba byte `ef bb bf` ở đầu). Java không tự bỏ BOM; kiểm tra và cắt ký tự `﻿` ở dòng đầu.
- `UnsupportedCharsetException: windows-1258`: một số bản JRE rút gọn bỏ module `jdk.charsets`. Dùng JDK đầy đủ, hoặc thêm module đó khi tạo runtime bằng `jlink`.
- In ra `?` thay cho chữ có dấu: kiểm tra `locale` của terminal hoặc `LANG` của container, như bước 2.

<Reveal title="Mojibake đã lỡ lưu vào database thì cứu thế nào?">

Nếu chuỗi hỏng được tạo bằng cách giải mã UTF-8 theo windows-1252, làm ngược lại: `new String(bad.getBytes(Charset.forName("windows-1252")), StandardCharsets.UTF_8)`. Với `Nguyá»…n` cách này cho lại `Nguyễn`. Với `Ä�á»©c` thì không, vì byte `90` đã thành `�` ngay lần giải mã đầu. Phải sửa trên một bản sao, đếm số dòng còn chứa `�` sau khi sửa, và tìm lại dữ liệu gốc cho những dòng đó.

</Reveal>

<Reveal title="Tên file tiếng Việt trên macOS có vấn đề gì?">

Hệ thống file của macOS có thể trả tên file ở dạng NFD, trong khi tên bạn gõ trong code là NFC. `Files.exists(Path.of("Hà Nội.csv"))` vẫn đúng vì hệ thống file so sánh không phân biệt dạng chuẩn hoá, nhưng so sánh `Path.getFileName().toString()` với một chuỗi bằng `equals` có thể sai. Chuẩn hoá cả hai vế về NFC trước khi so sánh, như bước 5.

</Reveal>

<Reveal title="Khi nào vẫn dùng java.io thay vì NIO.2?">

Khi API bạn gọi chỉ nhận `InputStream` hay `Reader`: thư viện parse, body của HTTP request, `System.in`, resource trong file jar (`getResourceAsStream`). `Files` cũng trả về các kiểu đó (`newInputStream`, `newBufferedReader`), nên hai thế giới ghép được với nhau. Lớp `java.io.File` thì nên tránh trong code mới; cần thì đổi qua lại bằng `file.toPath()` và `path.toFile()`.

</Reveal>

<Reveal title="Files.writeString ghi được nửa chừng thì sao?">

Nếu process chết giữa chừng, file đích có thể chỉ còn một nửa. Cách an toàn cho file quan trọng là ghi ra file tạm trong cùng thư mục, rồi `Files.move(tmp, target, StandardCopyOption.ATOMIC_MOVE)`. Người đọc chỉ thấy bản cũ hoặc bản mới hoàn chỉnh.

</Reveal>

<Callout kind="ai">

Nhờ AI viết code đọc ghi file hoặc giải thích một stack trace về charset. AI hay viết `new FileReader(file)` hay `getBytes()` không truyền charset, dùng `Files.readAllLines` cho file lớn, hoặc quên đóng stream của `Files.lines` và `Files.walk`. Khi được hỏi về mojibake, nó hay đề xuất đổi sang ISO-8859-1 cho "hết lỗi". Kiểm tra lại: tìm mọi chỗ tạo `Reader`, `Writer`, `getBytes`, `new String(bytes)` và xem có charset tường minh không; chạy thử với file chứa chữ có dấu.

</Callout>

<Goal>

Dùng Jackson để chuyển record Java sang JSON và ngược lại, điều khiển tên trường, trường bị bỏ qua và kiểu `java.time`. Dùng `HttpClient` của JDK để gọi API: đặt timeout, gửi JSON, kiểm tra status code trước khi đọc body. Học xong bài này, bạn giải thích được:

- Vì sao bên cung cấp API thêm một trường mới vào JSON mà client Jackson 2 của bạn chết, còn client Jackson 3 thì không.
- Vì sao một service gọi API chậm có thể treo hết thread nếu không đặt timeout.
- Vì sao code Jackson cũ không biên dịch được khi đổi dependency sang Jackson 3.

</Goal>

<Knowledge>

### Data binding với Jackson

JSON là định dạng trao đổi dữ liệu phổ biến nhất giữa service. Java không có sẵn thư viện JSON trong JDK; **Jackson** là thư viện được dùng nhiều nhất, và là mặc định của Spring Boot. Cách dùng chính là **data binding**: ánh xạ thẳng giữa object Java và JSON.

```text
record Order(code, customer, amount, createdAt)
        |   mapper.writeValueAsString(order)        ^
        v                                            |   mapper.readValue(json, Order.class)
{"code":"DH-0001","customer":"...","amount":350000,"created_at":"2026-10-01T02:15:00Z"}
```

`JsonMapper` (lớp con của `ObjectMapper` dành cho JSON) giữ cấu hình và bộ nhớ đệm về cấu trúc các class. Tạo nó tốn kém, nhưng sau khi tạo thì thread-safe: tạo một lần và dùng chung cho cả ứng dụng. Jackson hiểu record: tên component là tên trường JSON, constructor chính dùng để tạo object khi đọc.

Annotation hay dùng:

| Annotation | Đặt ở | Tác dụng |
|---|---|---|
| `@JsonProperty("created_at")` | Component, field | Đổi tên trường JSON, khi API dùng `snake_case` còn Java dùng `camelCase` |
| `@JsonIgnore` | Component, field | Không ghi ra JSON và không đọc vào |
| `@JsonIgnoreProperties(ignoreUnknown = true)` | Class | Bỏ qua trường lạ cho riêng class này |
| `@JsonFormat(pattern = "dd/MM/yyyy")` | Component, field | Định dạng riêng cho ngày giờ |

Khi đọc một JSON có trường mà class không có, Jackson có hai cách: ném lỗi, hoặc bỏ qua. Bỏ qua (gọi là **tolerant reader**) giúp client không chết khi bên cung cấp API thêm trường mới; ném lỗi giúp phát hiện gõ sai tên trường. Cấu hình bằng `DeserializationFeature.FAIL_ON_UNKNOWN_PROPERTIES`.

### Jackson 2 hay Jackson 3

Jackson 3.0 ra ngày 3/10/2025. Bản mới nhất trên Maven Central ngày 03/10/2026 là **3.2.3**; nhánh 2 vẫn được bảo trì song song, mới nhất là 2.22.3.

| | Jackson 2.x | Jackson 3.x |
|---|---|---|
| Maven groupId | `com.fasterxml.jackson.core` | `tools.jackson.core` |
| Package trong code | `com.fasterxml.jackson.databind` | `tools.jackson.databind` |
| Package annotation | `com.fasterxml.jackson.annotation` | Giữ nguyên `com.fasterxml.jackson.annotation` |
| Exception | `JsonProcessingException`, checked | `JacksonException`, unchecked |
| Kiểu `java.time` | Cần thêm module `jackson-datatype-jsr310` | Có sẵn trong databind |
| Trường lạ khi đọc | Mặc định ném lỗi | Mặc định bỏ qua |
| Ngày giờ khi ghi | Mặc định là số (timestamp) | Mặc định là chuỗi ISO-8601 |
| JDK tối thiểu | 8 | 17 |

**Bài này chọn Jackson 3 vì đây là nhánh phát triển chính cho dự án mới trên Java 17 trở lên, có sẵn hỗ trợ `java.time` và mặc định an toàn hơn; bạn vẫn cần đọc được Jackson 2 vì phần lớn code hiện có dùng package `com.fasterxml.jackson`.** Đổi dependency từ 2 lên 3 không chỉ là đổi số phiên bản: phải đổi `import`, và mọi chỗ bắt `JsonProcessingException` phải sửa.

<Callout kind="production">

Một đối tác thanh toán thêm trường `"channel"` vào JSON trả về, không báo trước vì với họ đây là thay đổi tương thích. Service dùng Jackson 2 với cấu hình mặc định bắt đầu ném `UnrecognizedPropertyException` ở mọi response, và mọi đơn hàng đều lỗi cho tới khi bản sửa được deploy. Client đọc API bên ngoài nên bỏ qua trường lạ. Ngược lại, API của chính bạn nhận request từ client có thể bật kiểm tra chặt để báo lỗi khi client gửi sai tên trường.

</Callout>

<Check id="j9.3.jackson-versions">Kể được ba khác biệt giữa Jackson 2 và 3 (package, exception, mặc định với trường lạ hoặc `java.time`) và giải thích vì sao client đọc API ngoài nên bỏ qua trường lạ.</Check>

### HttpClient của JDK

Từ Java 11 (JEP 321), gói `java.net.http` có HTTP client hỗ trợ HTTP/1.1, HTTP/2, gọi đồng bộ và bất đồng bộ, không cần thư viện ngoài. Ba thành phần:

```text
HttpClient   (tạo một lần, dùng chung: connection pool, connectTimeout, HTTP/2)
    |
    |  send(request, BodyHandler)        đồng bộ: thread chờ tới khi có response
    |  sendAsync(request, BodyHandler)   bất đồng bộ: trả CompletableFuture ngay
    v
HttpRequest  (URI, method, header, body, timeout của riêng request; bất biến)
    |
    v
HttpResponse<T>  statusCode(), headers(), body() kiểu T do BodyHandler quyết định
```

| Thành phần | Ví dụ | Ghi chú |
|---|---|---|
| Body gửi đi | `BodyPublishers.ofString(json)` | Mã hoá UTF-8 |
| Body nhận về | `BodyHandlers.ofString()`, `ofFile(path)`, `discarding()` | `ofString` đọc charset từ header `Content-Type`, mặc định UTF-8 |
| Timeout kết nối | `HttpClient.newBuilder().connectTimeout(...)` | Chờ tối đa bao lâu để mở kết nối |
| Timeout request | `HttpRequest.newBuilder().timeout(...)` | Chờ tối đa bao lâu để có response |

Hai điều hay bị quên:

- **Không đặt timeout thì chờ mãi.** Mặc định `HttpClient` không có timeout. Một API bên ngoài treo sẽ giữ thread của bạn mãi mãi; khi mọi thread trong pool đều chờ, service của bạn ngừng phục vụ dù CPU rảnh.
- **Status code lỗi không phải exception.** Response 404 hay 500 vẫn là response hợp lệ với `HttpClient`. Bạn phải tự kiểm tra `statusCode()` trước khi parse body, nếu không sẽ đem trang lỗi HTML đi parse thành JSON.

<Check id="j9.3.http-model">Giải thích được vai trò của `HttpClient`, `HttpRequest`, `BodyHandler`, khác biệt giữa connect timeout và request timeout, và vì sao phải tự kiểm tra status code.</Check>

</Knowledge>

### 1. Chạy server giả lập

Server có ba đường dẫn: `GET /orders` trả danh sách đơn, `POST /orders` nhận đơn mới, `GET /slow` chờ 3 giây mới trả lời.

<Terminal where="mac" title="Tab 1: src/OrderServer.java">

```bash
cd ~/masteva-j9
cat > src/OrderServer.java <<'EOF'
import com.sun.net.httpserver.HttpExchange;
import com.sun.net.httpserver.HttpServer;
import java.io.IOException;
import java.net.InetSocketAddress;
import java.nio.charset.StandardCharsets;

/** Server giả lập API đơn hàng cho lab J9.3. Chỉ dùng để học, không dùng cho production. */
public class OrderServer {
    static final String ORDERS = """
            [
              {"code":"DH-0001","customer":"Nguyễn Thị Hồng Nhung","amount":350000,
               "created_at":"2026-10-01T02:15:00Z","channel":"web"},
              {"code":"DH-0002","customer":"Trần Văn Đức","amount":1200000,
               "created_at":"2026-10-01T16:45:30Z","channel":"pos"}
            ]
            """;

    public static void main(String[] args) throws IOException {
        HttpServer server = HttpServer.create(new InetSocketAddress("localhost", 8099), 0);
        server.createContext("/orders", exchange -> {
            String method = exchange.getRequestMethod();
            System.out.println(method + " " + exchange.getRequestURI());
            if (method.equals("GET")) {
                send(exchange, 200, ORDERS);
            } else if (method.equals("POST")) {
                String body = new String(exchange.getRequestBody().readAllBytes(), StandardCharsets.UTF_8);
                System.out.println("  body: " + body);
                send(exchange, 201, "{\"code\":\"DH-0006\",\"status\":\"CREATED\"}");
            } else {
                send(exchange, 405, "{\"error\":\"method not allowed\"}");
            }
        });
        server.createContext("/slow", exchange -> {
            System.out.println("GET /slow, chờ 3 giây");
            try {
                Thread.sleep(3_000);
            } catch (InterruptedException e) {
                Thread.currentThread().interrupt();
            }
            send(exchange, 200, "{}");
        });
        server.start();
        System.out.println("OrderServer chạy ở http://localhost:8099");
    }

    static void send(HttpExchange exchange, int status, String json) throws IOException {
        byte[] bytes = json.getBytes(StandardCharsets.UTF_8);
        exchange.getResponseHeaders().set("Content-Type", "application/json; charset=utf-8");
        exchange.sendResponseHeaders(status, bytes.length);
        try (var out = exchange.getResponseBody()) {
            out.write(bytes);
        }
    }
}
EOF
```

### 4. Gọi API bằng HttpClient

<Terminal where="mac" title="Tab 1: OrderClient.java">

```bash
cd ~/masteva-j9/order-client
cat > src/main/java/vn/masteva/orders/OrderClient.java <<'EOF'
package vn.masteva.orders;

import java.io.IOException;
import java.net.URI;
import java.net.http.HttpClient;
import java.net.http.HttpRequest;
import java.net.http.HttpResponse;
import java.net.http.HttpTimeoutException;
import java.time.Duration;
import java.time.ZoneId;
import java.time.format.DateTimeFormatter;
import java.util.List;
import tools.jackson.core.type.TypeReference;
import tools.jackson.databind.json.JsonMapper;

public class OrderClient {
    private static final URI BASE = URI.create("http://localhost:8099");
    private static final ZoneId VN = ZoneId.of("Asia/Ho_Chi_Minh");
    private static final DateTimeFormatter DISPLAY = DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm");

    // Tạo một lần, dùng chung cho mọi request: cả hai đều thread-safe
    private final HttpClient http = HttpClient.newBuilder()
            .connectTimeout(Duration.ofSeconds(2))
            .build();
    private final JsonMapper mapper = JsonMapper.builder().build();

    List<Order> listOrders() throws IOException, InterruptedException {
        HttpRequest request = HttpRequest.newBuilder(BASE.resolve("/orders"))
                .header("Accept", "application/json")
                .timeout(Duration.ofSeconds(5))
                .GET()
                .build();
        HttpResponse<String> response = http.send(request, HttpResponse.BodyHandlers.ofString());
        if (response.statusCode() != 200) {
            throw new IOException("GET /orders trả về " + response.statusCode());
        }
        return mapper.readValue(response.body(), new TypeReference<List<Order>>() {});
    }

    String createOrder(NewOrder order) throws IOException, InterruptedException {
        String json = mapper.writeValueAsString(order);
        HttpRequest request = HttpRequest.newBuilder(BASE.resolve("/orders"))
                .header("Content-Type", "application/json")
                .timeout(Duration.ofSeconds(5))
                .POST(HttpRequest.BodyPublishers.ofString(json))
                .build();
        HttpResponse<String> response = http.send(request, HttpResponse.BodyHandlers.ofString());
        if (response.statusCode() != 201) {
            throw new IOException("POST /orders trả về " + response.statusCode() + ": " + response.body());
        }
        return response.body();
    }

    int status(String path, Duration timeout) throws IOException, InterruptedException {
        HttpRequest request = HttpRequest.newBuilder(BASE.resolve(path)).timeout(timeout).build();
        return http.send(request, HttpResponse.BodyHandlers.discarding()).statusCode();
    }

    public static void main(String[] args) throws Exception {
        OrderClient client = new OrderClient();
        for (Order order : client.listOrders()) {
```

### Khi gặp lỗi

<Callout kind="pitfall">

- `java.net.BindException: Address already in use` khi chạy server: cổng 8099 đang bị chiếm, thường là server cũ ở tab khác chưa dừng. Tìm bằng `lsof -i :8099`, dừng tiến trình đó, hoặc đổi cổng ở cả server và client.
- `package com.fasterxml.jackson.databind does not exist`: code viết cho Jackson 2 nhưng dependency là Jackson 3. Đổi `import` sang `tools.jackson.databind`; chỉ annotation giữ package `com.fasterxml.jackson.annotation`.
- `UnrecognizedPropertyException`: JSON có trường mà class không có. Thêm component vào record nếu cần dữ liệu đó, hoặc tắt `FAIL_ON_UNKNOWN_PROPERTIES`.
- `MismatchedInputException: Cannot deserialize value of type ... from Array value`: JSON là mảng `[...]` nhưng bạn đọc vào một object. Dùng `TypeReference<List<Order>>`.
- `release version 25 not supported`: Maven đang chạy bằng JDK cũ hơn 25. Kiểm tra lại `mvn -v` và `JAVA_HOME`.

<DeepDive>

<Reveal title="Khi nào dùng sendAsync?">

`sendAsync` trả `CompletableFuture<HttpResponse<T>>` ngay, không giữ thread trong lúc chờ. Nó hữu ích khi cần gọi nhiều API cùng lúc rồi gộp kết quả, ví dụ lấy giá từ ba nhà vận chuyển. Từ Java 21, virtual thread làm cách gọi đồng bộ `send` trở nên rẻ: mỗi request chạy trên một virtual thread, code vẫn đọc từ trên xuống. J11 so sánh hai cách này.

</Reveal>

<Reveal title="Vì sao không tạo HttpClient hay JsonMapper mới cho mỗi request?">

`HttpClient` giữ connection pool: request sau dùng lại kết nối TCP (và TLS) đã mở, bỏ qua bước bắt tay tốn hàng chục mili giây. Tạo client mới mỗi lần làm mất pool và có thể để lại kết nối mở. `JsonMapper` lưu đệm thông tin về cấu trúc mỗi class sau lần dùng đầu; tạo mới mỗi lần là làm lại việc đó. Cả hai đều thread-safe sau khi tạo, nên một instance cho cả ứng dụng là đủ. Trong Spring Boot, framework tạo sẵn và inject cho bạn.

</Reveal>

<Reveal title="Có nên để Jackson ghi thẳng entity database ra JSON?">

Không nên. Entity thay đổi theo database; API là hợp đồng với client. Gắn hai thứ vào nhau thì đổi tên một cột là vỡ API, và dễ lộ trường nhạy cảm như mật khẩu đã băm. Tạo record riêng cho request và response (DTO, data transfer object) như `Order` và `NewOrder` ở bài này, rồi chuyển đổi giữa entity và DTO.

</Reveal>

<Reveal title="Tiền nên để kiểu gì trong JSON?">

Bài này dùng `long` theo đơn vị đồng, như J1. JSON chỉ có một kiểu số; nhiều client (JavaScript chẳng hạn) đọc số thành `double`, mất chính xác với số lớn hơn khoảng 9 triệu tỷ hoặc với số lẻ. Với tiền có phần lẻ, nhiều API gửi dạng chuỗi (`"amount":"125000.50"`) hoặc số nguyên ở đơn vị nhỏ nhất, kèm mã tiền tệ. Phía Java dùng `BigDecimal` hoặc `long`, không dùng `double`.

</Reveal>

AI hay trộn Jackson 2 và 3: import `com.fasterxml.jackson.databind` trong project Jackson 3, bắt `JsonProcessingException`, hoặc thêm module `jsr310` không còn cần.

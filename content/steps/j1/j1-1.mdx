<Goal>

Hiểu JDK gồm những gì, chọn được bản phân phối và phiên bản phù hợp, rồi tự biên dịch và chạy một chương trình Java nhỏ bằng dòng lệnh. Học xong bài này, bạn giải thích được ba chuyện hay gặp:

- Vì sao ứng dụng chạy tốt trên máy bạn nhưng trên server báo `UnsupportedClassVersionError`.

<Knowledge>

### JDK gồm những gì

**JDK (Java Development Kit)** là bộ công cụ để viết và chạy Java. Bên trong có **JVM (Java Virtual Machine)**, tức máy ảo chạy bytecode, thư viện chuẩn và các lệnh sau:

| Lệnh | Việc nó làm | Bạn dùng khi |
|---|---|---|
| `javac` | Biên dịch file `.java` thành bytecode `.class` | Build thủ công, hoặc gián tiếp qua Maven, Gradle |
| `java` | Khởi động JVM và chạy một class có `main` | Chạy ứng dụng, chạy thẳng file nguồn |
| `jshell` | REPL (vòng đọc, chạy, in kết quả): gõ từng dòng Java và xem kết quả ngay | Thử API, kiểm tra một phép tính |
| `javap` | Đọc file `.class`: phiên bản, method, bytecode | Kiểm tra class được build cho Java bản nào |
| `javadoc` | Sinh tài liệu HTML từ chú thích trong code | Bài J1.3 |
| `jdb` | Debugger dòng lệnh | Bài J1.2 |

Từ Java 11 không còn bản **JRE** (chỉ có phần chạy) tách riêng từ Oracle. Bạn cài JDK cho máy lập trình; image container có thể dùng bản JRE do các hãng như Eclipse Temurin đóng gói.

<Check id="j1.1.jdk-tools">Kể được `javac`, `java`, `jshell`, `javap` mỗi lệnh làm gì.</Check>

### Từ file .java tới chương trình đang chạy

```text
src/Main.java, src/Invoice.java        mã nguồn, bạn viết
        |
        |  javac -d out src/*.java
        v
out/Main.class, out/Invoice.class      bytecode, giống nhau trên Mac, Linux, Windows
        |
        |  java -cp out Main
        v
JVM: nạp class -> kiểm tra bytecode -> thông dịch -> JIT dịch đoạn chạy nhiều thành mã máy
```

- `javac` không tạo ra file chạy được trực tiếp. Nó tạo bytecode, một dạng lệnh trung gian mà chỉ JVM hiểu.
- `-cp` (classpath) cho JVM biết tìm file `.class` ở đâu. Tên class `Main` không có đuôi `.class`.
- **JIT (Just-In-Time compiler)** theo dõi đoạn code chạy nhiều lần và dịch nó thành mã máy lúc đang chạy. Vì vậy ứng dụng Java thường chậm ở những request đầu, rồi nhanh dần.

Mỗi file `.class` ghi **major version** của bytecode. JVM chỉ chạy được bytecode có version bằng hoặc thấp hơn version của nó:

| Java | 8 | 11 | 17 | 21 | 25 |
|---|---|---|---|---|---|
| Major version | 52 | 55 | 61 | 65 | 69 |

<Check id="j1.1.class-version">Giải thích được vì sao class build bằng JDK 25 không chạy trên JVM 21, và đọc được major version bằng `javap`.</Check>

### Bản phân phối và phiên bản LTS

Mã nguồn của Java nằm ở dự án **OpenJDK**. Nhiều hãng lấy cùng mã nguồn đó, build, kiểm thử và phát hành bản của mình. Các bản này chạy code của bạn như nhau; chúng khác ở giấy phép, lịch phát hành bản vá và hỗ trợ trả phí.

| Bản phân phối | Ai phát hành | Ghi chú |
|---|---|---|
| Eclipse Temurin | Eclipse Adoptium | Miễn phí, phổ biến nhất để cài trên máy và trong image Docker |
| Oracle JDK | Oracle | Có điều khoản giấy phép riêng; đọc kỹ trước khi dùng cho production |
| Amazon Corretto | Amazon | Hay gặp trên AWS |
| Microsoft Build of OpenJDK | Microsoft | Hay gặp trên Azure |

Java ra một phiên bản mới mỗi 6 tháng, vào tháng 3 và tháng 9. Cứ hai năm có một bản **LTS (Long-Term Support)**, được vá lỗi và bảo mật trong nhiều năm. Bản không phải LTS chỉ được vá tới khi bản kế tiếp ra.

| Phiên bản | Loại | Phát hành |
|---|---|---|
| 21 | LTS | 9/2023 |
| 25 | LTS | 9/2025 |
| 26, 27 | Không LTS | 3/2026, 9/2026 |
| 29 | LTS, theo kế hoạch | 9/2027 |

Với dự án mới, chọn **21 hoặc 25**. Bài này kiểm tra trên JDK 25. Theo lịch của Oracle, Oracle hỗ trợ Premier cho Java 25 tới 9/2030; các hãng khác công bố lịch riêng trên trang của họ.

<Callout kind="production">

CI build ứng dụng bằng JDK 25, nhưng Dockerfile chạy bằng image JRE 21. Container khởi động là chết ngay với dòng `UnsupportedClassVersionError ... class file version 69.0 ... only recognizes class file versions up to 65.0`. Đọc hai con số là biết: code build cho Java 25 (69), JVM là Java 21 (65). Cách sửa là dùng cùng phiên bản cho build và runtime, hoặc build với `--release 21` nếu buộc phải chạy trên 21.

</Callout>

<Check id="j1.1.lts-choice">Giải thích được bản phân phối khác phiên bản thế nào, và vì sao dự án mới nên chọn một bản LTS.</Check>

### Chạy thẳng file nguồn và jshell

Với chương trình nhỏ, bạn không cần gọi `javac` trước:

- Từ Java 11, `java Main.java` biên dịch file trong bộ nhớ rồi chạy ngay, không ghi file `.class` ra đĩa.
- Từ Java 22 (JEP 458), nếu `Main.java` dùng class ở file khác cùng thư mục, `java` tự tìm và biên dịch file đó.

**jshell** là REPL của Java. Bạn gõ một biểu thức, jshell in kết quả ngay, không cần class hay `main`. Biểu thức không gán vào biến nào sẽ được jshell đặt tên tự động là `$1`, `$2`, và cứ thế tăng dần. Lệnh của chính jshell bắt đầu bằng `/`: `/vars` liệt kê biến, `/open` nạp một file, `/exit` thoát.

</Knowledge>

<Resources>

- [Oracle Java SE Support Roadmap](https://www.oracle.com/java/technologies/java-se-support-roadmap.html): bảng phiên bản nào là LTS và hỗ trợ tới khi nào.
- [Eclipse Temurin](https://adoptium.net/temurin/releases/): chọn hệ điều hành, kiến trúc (`aarch64` cho Mac chip M, `x64` cho Intel) và phiên bản để tải bản cài.
- [Lệnh javac (Java SE 25)](https://docs.oracle.com/en/java/javase/25/docs/specs/man/javac.html): đọc các tuỳ chọn `-d`, `--class-path` và `--release`.
- [JEP 458: Launch Multi-File Source-Code Programs](https://openjdk.org/jeps/458): phần "Description" giải thích `java` tìm các file nguồn khác như thế nào.
- [JShell trên dev.java](https://dev.java/learn/jshell-tool/): các lệnh `/` hay dùng và phím Tab để gợi ý.

</Resources>

Nếu chưa có JDK 21 hoặc 25, cài Temurin 25 bằng Homebrew:

<Terminal where="mac" title="Chỉ chạy khi chưa có JDK">

```bash
brew install --cask temurin@25
```

</Terminal>

Lệnh cài đặt **không được chạy** khi kiểm chứng bài này, vì máy kiểm chứng đã có JDK; tên gói đã được kiểm bằng `brew install --cask --dry-run temurin@25`. Cách khác là tải file `.pkg` từ trang Temurin, hoặc dùng [SDKMAN](https://sdkman.io/) (`sdk list java` để xem mã, rồi `sdk install java <mã>-tem`). Trên Linux, SDKMAN cho cùng một cách cài trên mọi bản phân phối; gói của hệ điều hành như `openjdk-25-jdk` chỉ có ở các bản phân phối đủ mới.

<Callout kind="pitfall">

`brew install --cask temurin` (không có `@25`) cài bản mới nhất, hiện là 27, không phải LTS. Luôn ghi rõ phiên bản. Nếu `java -version` và `javac -version` báo hai bản khác nhau, máy bạn có nhiều JDK và `PATH` đang trỏ lẫn lộn. Trên Mac, lệnh `java` mặc định (`/usr/bin/java`) chạy JDK mà `JAVA_HOME` trỏ tới, nên hãy gán `JAVA_HOME` bằng output của `/usr/libexec/java_home -v 25` trong `~/.zshrc` rồi mở lại Terminal. Trên Linux, đặt `$JAVA_HOME/bin` đứng đầu `PATH`.

</Callout>

### 2. Tạo project nhỏ

Project này dùng tiếp ở bài J1.2 và J1.3. Đó là một hoá đơn bán hàng: cộng giá các món và tính VAT 10%.

<Terminal where="mac" title="Tạo src/Invoice.java và src/Main.java">

```bash
mkdir -p ~/masteva-j1/src && cd ~/masteva-j1
cat > src/Invoice.java <<'EOF'
import java.util.ArrayList;
import java.util.List;

public class Invoice {
    private final List<Long> prices = new ArrayList<>();

    public void add(long price) {
        prices.add(price);
    }

    public long subtotal() {
        long sum = 0;
        for (long price : prices) {
            sum += price;
        }
        return sum;
    }

    public long vat() {
        return subtotal() * 10 / 100;
    }

    public long total() {
        return subtotal() + vat();
    }
}
EOF
cat > src/Main.java <<'EOF'
public class Main {
    public static void main(String[] args) {
        Invoice invoice = new Invoice();
        invoice.add(120_000);
        invoice.add(180_000);
        System.out.println("subtotal=" + invoice.subtotal());
        System.out.println("vat=" + invoice.vat());
        System.out.println("total=" + invoice.total());
    }
}
EOF
```

</Terminal>

Tiền để ở kiểu `long`, đơn vị là đồng. Dấu `_` trong `120_000` chỉ giúp dễ đọc, trình biên dịch bỏ qua nó.

### 5. Phiên bản bytecode

<Terminal where="mac">

```bash
javap -v out/Main.class | grep major
javac --release 21 -d out21 src/*.java && javap -v out21/Main.class | grep major
```

</Terminal>

<Predict question="Hai dòng major version khác nhau thế nào?">

```text
  major version: 69
  major version: 65
```

`--release 21` bảo `javac` của JDK 25 sinh bytecode cho Java 21 và chỉ cho dùng API có trong Java 21. Thư mục `out21` chạy được trên JVM 21, thư mục `out` thì không.

</Predict>

Nếu máy bạn có thêm JDK 21, thử chạy bytecode 69 trên JVM 21 để thấy lỗi thật:

</Terminal>

<Expected>


### 6. Thử nhanh với jshell

<Terminal where="mac">

```bash
cd ~/masteva-j1 && jshell
```

</Terminal>

Gõ lần lượt từng dòng sau dấu nhắc `jshell>`:

```text
2 + 3 * 4
99_999 * 10 / 100
/open src/Invoice.java
var inv = new Invoice()
inv.add(99_999)
inv.vat()
/exit
```

<Predict question="99_999 * 10 / 100 cho ra bao nhiêu?">

```text
jshell> 2 + 3 * 4
$1 ==> 14

jshell> 99_999 * 10 / 100
$2 ==> 9999
```

Hai toán hạng đều là số nguyên nên `/` là **phép chia nguyên**: phần thập phân bị bỏ, không làm tròn. `inv.vat()` cũng trả `9999` vì cùng công thức. Với tiền, đây là quyết định nghiệp vụ: làm tròn xuống, làm tròn gần nhất hay dùng `BigDecimal`. Đừng để nó xảy ra tình cờ.

</Predict>

<Expected>

```text
jshell> /open src/Invoice.java

jshell> var inv = new Invoice()
inv ==> Invoice@17f052a3

jshell> inv.add(99_999)

jshell> inv.vat()
$8 ==> 9999
```

</Expected>

`/open` nạp `Invoice.java` vào phiên jshell, nên bạn gọi được `new Invoice()` mà không cần `main`. Phần sau `Invoice@` khác nhau mỗi lần chạy. `inv.vat()` mang số `$8` vì jshell đánh số cả những gì `/open` nạp vào (hai dòng `import` và class), và cả lệnh `inv.add(...)`.

<Check id="j1.1.lab-jshell">Dùng jshell tính được một biểu thức, nạp `Invoice.java` bằng `/open` và gọi method của nó.</Check>

<DeepDive>

<Reveal title="Đã có java Main.java, sao dự án thật vẫn cần javac hay Maven?">

Chế độ chạy từ mã nguồn biên dịch lại toàn bộ mỗi lần chạy và không tạo file `.class` hay `.jar`. Nó không quản lý thư viện bên ngoài, không chạy test, không đóng gói. Nó hợp với script, ví dụ, bài tập. Dự án có nhiều package và dependency cần build tool như Maven hoặc Gradle, học ở J7.

</Reveal>

<Reveal title="Vì sao nên dùng --release thay vì -source và -target?">

`-source 21 -target 21` chỉ đổi cú pháp được phép và version bytecode, nhưng vẫn biên dịch với thư viện chuẩn của JDK 25. Code có thể gọi một method chỉ có từ Java 25, biên dịch thành công, rồi chết với `NoSuchMethodError` trên JVM 21. `--release 21` kiểm tra cả API, nên lỗi lộ ra ngay lúc biên dịch.

</Reveal>

<Reveal title="Java 25 có cách viết main ngắn hơn không?">

Có. Từ Java 25 (JEP 512), một file chỉ cần `void main() { IO.println("Xin chao"); }`, không cần `public class` hay `static`. Cách này dành cho chương trình nhỏ và người mới học. Code trong các dự án hiện tại vẫn dùng `public static void main(String[] args)`, nên bạn cần đọc được cả hai.

</Reveal>

Kiểm tra lại bằng `java -version`, `javap -v ... | grep major` và trang Support Roadmap của Oracle.

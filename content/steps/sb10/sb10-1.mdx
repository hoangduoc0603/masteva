<Goal>

Thêm hai tính năng mà gần như service nghiệp vụ nào cũng có: nhận file người dùng tải lên và xuất báo cáo. Học xong bài này, bạn giải thích được:

- Vì sao file `avatar.png` vẫn có thể là một đoạn script, và kiểm loại file thế nào cho đúng.
- Vì sao link tải file "tự hết hạn sau 5 phút" mà ứng dụng không cần làm gì, và vì sao sửa một ký tự trong link là bị từ chối.
- Vì sao xuất 100.000 dòng Excel làm instance chết vì `OutOfMemoryError` với heap 256 MB, trong khi cách khác chỉ cần khoảng 30 MB.
- Vì sao PDF xuất ra mất hết chữ có dấu, và vì sao `curl -J` lưu file tải về thành `Bao cao _on hang.xlsx` trong khi trình duyệt giữ đúng tên tiếng Việt.

</Goal>

<Knowledge>

### File không nằm trên đĩa của ứng dụng

Ba chỗ hay được nghĩ tới để lưu file người dùng tải lên:

| Lưu ở | Ưu | Vấn đề |
|---|---|---|
| Đĩa của máy chạy ứng dụng | Đơn giản | Hai instance không thấy file của nhau; container khởi động lại là mất; backup riêng |
| PostgreSQL (`bytea`, large object) | Cùng transaction với dữ liệu | Database phình to, backup và replication chậm, mỗi lần tải file đi qua connection pool |
| **Object storage** (S3 và tương thích) | Không giới hạn dung lượng, bền, rẻ, trình duyệt tải trực tiếp | Không cùng transaction với database, phải tự giữ nhất quán |

Cách phổ biến: **byte của file nằm ở object storage, metadata nằm trong PostgreSQL** (tên gốc, loại, kích thước, mã băm, ai tải lên, key trỏ tới object).

**Object storage** lưu **object** (một dãy byte cộng metadata) trong **bucket**, mỗi object có một **key** dạng chuỗi như `uploads/54c0940d-...`. Không có thư mục thật, không sửa được một phần object: ghi là ghi đè cả object. **S3 API** của Amazon đã thành chuẩn chung: AWS S3, Cloudflare R2, Google Cloud Storage (chế độ tương thích), và các phần mềm tự host như MinIO, Garage, SeaweedFS, RustFS đều nói cùng giao thức. Code dùng AWS SDK for Java 2.x chạy với tất cả, chỉ đổi `endpoint` và khoá.

Hai chi tiết khi trỏ SDK sang dịch vụ không phải AWS:

- **Path-style** (`http://host/bucket/key`) thay vì **virtual-hosted style** (`http://bucket.host/key`). Storage chạy trên `localhost` không có DNS cho `sb10-files.localhost`, nên lab bật `forcePathStyle(true)`.
- **Region** vẫn phải đặt vì nó nằm trong chữ ký; storage tự host thường chấp nhận `us-east-1`.

<Callout kind="pitfall">

**Chọn S3 tự host cho lab:** MinIO, lựa chọn quen thuộc nhất, đã archive repository bản cộng đồng (4/2026) và không còn image cộng đồng chính thức: ngày chạy lab, `docker pull minio/minio` báo `pull access denied`, `quay.io/minio/minio` trả 401. Lab dùng **RustFS** (`rustfs/rustfs`, giấy phép Apache 2.0), image chính thức của dự án, nói S3 API như MinIO. RustFS mới phát hành bản GA (9/2026), nên trước khi dùng cho production cần tự đánh giá độ ổn định và cách vận hành; SeaweedFS là lựa chọn tự host trưởng thành hơn, còn khi chạy trên cloud thì dùng thẳng AWS S3, Cloudflare R2 hay Google Cloud Storage. Code trong bài không phụ thuộc vào lựa chọn đó.

</Callout>

### Upload qua ứng dụng

```text
 trình duyệt                Spring MVC (Tomcat)                    RustFS (S3)         PostgreSQL
     | POST /files, multipart/form-data
     |------------------------->| 1. Tomcat đọc body, ghi phần file ra file tạm
     |                          |    quá max-file-size / max-request-size -> 413
     |                          | 2. đọc vài byte đầu: Tika nhận ra image/png
     |                          |    không thuộc danh sách cho phép -> 415
     |                          | 3. PutObject key = uploads/<uuid> ------->|
     |                          |    (tính SHA-256 trong lúc stream)        |
     |                          | 4. INSERT stored_files (metadata) ------------------------>|
     |<-------------------------| 5. trả id, loại, kích thước, sha256
```

**Multipart** là định dạng body của form có `<input type="file">`. Spring Boot cấu hình nó qua `spring.servlet.multipart.*`:

| Thuộc tính | Mặc định | Ý nghĩa |
|---|---|---|
| `max-file-size` | 1MB | Một file vượt mức này thì từ chối |
| `max-request-size` | 10MB | Tổng cả request (nhiều file cộng các trường khác) |
| `file-size-threshold` | 0B | File lớn hơn mức này được ghi ra đĩa tạm; 0 nghĩa là luôn ghi ra đĩa |

Vượt giới hạn, Spring ném `MaxUploadSizeExceededException`; với `spring.mvc.problemdetails.enabled=true` (SB1.3) client nhận `413 Content Too Large` dạng Problem Details. `MultipartFile.getInputStream()` gọi được nhiều lần: một lần để đoán loại, một lần để đẩy lên storage.

**Không tin tên file, không tin header `Content-Type` của phần file.** Cả hai do client tự đặt. Kiểm loại bằng **magic bytes**, vài byte đầu đặc trưng của từng định dạng: PNG bắt đầu bằng `89 50 4E 47`, PDF bằng `%PDF-`. **Apache Tika** (`tika-core`) đọc các byte đó và trả loại MIME; lab dùng `Tika.detect(InputStream)`, không truyền tên file để Tika không đoán theo đuôi. Những điều cần làm thêm:

- **Danh sách cho phép**, không phải danh sách cấm. SVG là XML có thể chứa `<script>`; HTML tải lên rồi mở trên cùng domain là XSS.
- **Key do server sinh** (`uploads/<uuid>`), không dùng tên người dùng gửi: tránh `../../etc/passwd`, tránh hai người cùng tên file ghi đè nhau. Tên gốc chỉ lưu trong metadata.
- **Trả file với `Content-Disposition: attachment`** để trình duyệt tải về thay vì hiển thị, và `X-Content-Type-Options: nosniff` để trình duyệt không tự đoán loại. Header này nên đặt ở proxy hay CDN phía trước storage: MinIO tự gửi nó, RustFS của lab thì không.
- Magic bytes chỉ nói định dạng, không nói file vô hại: ảnh vẫn mang EXIF có toạ độ GPS, PDF vẫn có thể chứa mã độc. Quét virus (ClamAV), mã hoá lại ảnh, và phục vụ file từ một domain riêng là các lớp phòng thủ tiếp theo.

**Nhất quán giữa storage và database.** PutObject và INSERT không cùng transaction. Lab ghi object trước, metadata sau: nếu INSERT lỗi, còn lại một object mồ côi, vô hại và dọn được bằng job định kỳ (so key trong bucket với bảng). Làm ngược lại, database có dòng trỏ tới object không tồn tại, lỗi lộ ra cho người dùng.

### Presigned URL

Bucket để **private**. Muốn cho trình duyệt tải một object, ứng dụng không stream byte qua chính nó mà tạo một **presigned URL**: URL chứa sẵn chữ ký SigV4 tính bằng secret key, cho phép đúng một thao tác (GET object này) tới một thời điểm hết hạn.

```text
 trình duyệt          ứng dụng                                     RustFS (S3)
     | GET /files/{id}/download
     |------------------->| kiểm tra quyền, đọc object_key từ PostgreSQL
     |                    | S3Presigner ký: GET + key + hạn 300 s
     |                    | + response-content-disposition (tên file gốc)
     |<-------------------| 302 Location: http://localhost:9410/...&X-Amz-Signature=...
     |------------------------------------------------------------------>| tính lại chữ ký
     |<------------------------------------------------------------------| 200 + byte của file
```

- Ký là phép tính cục bộ, không gọi mạng. Storage tự kiểm chữ ký và hạn; đổi bất kỳ tham số nào (hạn, key, tên file) thì chữ ký không khớp, trả `403 SignatureDoesNotMatch`.
- Ai có URL thì tải được tới khi hết hạn, và không thu hồi riêng một URL được. Giữ hạn ngắn (vài phút) và kiểm quyền **trước** khi ký. SigV4 cho hạn tối đa 7 ngày.
- Tham số `response-content-disposition` khiến storage trả header `Content-Disposition` theo ý ứng dụng, nên file tải về mang tên gốc thay vì UUID.
- Chiều ngược lại, **presigned PUT** cho trình duyệt tải thẳng file lớn lên storage mà không đi qua ứng dụng. Đổi lại, ứng dụng không còn chặn được ở bước 1 và 2 của sơ đồ upload; Đào sâu bàn cách kiểm sau.

<Callout kind="production">

Ứng dụng chạy trong Docker Compose hoặc Kubernetes gọi storage qua tên nội bộ `http://storage:9000`. Presigned URL ký với host đó, trình duyệt của người dùng không phân giải được `storage`. Sửa bằng cách thay host trong URL thì hỏng chữ ký, vì host nằm trong chuỗi được ký. Cách đúng: `S3Presigner` dùng endpoint công khai (ví dụ `https://files.example.com`), còn `S3Client` dùng endpoint nội bộ, và proxy phía trước giữ nguyên header `Host`.

</Callout>

### Xuất Excel: XSSF và SXSSF

File `.xlsx` là một file zip chứa các file XML. **Apache POI** có hai cách ghi nó:

| Lớp | Định dạng | Cách làm | Bộ nhớ |
|---|---|---|---|
| `XSSFWorkbook` | `.xlsx` | Mỗi ô là một cây đối tượng XML trong heap | Tăng theo số ô; đọc lại và sửa được mọi ô |
| `SXSSFWorkbook` | `.xlsx` | Chỉ giữ một **cửa sổ** N dòng gần nhất, dòng cũ hơn ghi ra file tạm | Gần như cố định; dòng đã ghi ra file không đọc lại được |

```text
 SXSSFWorkbook(100)
   createRow(1..100)     -> giữ trong heap
   createRow(101)        -> dòng 1 được ghi ra file tạm poi-sxssf-sheet*.xml, xoá khỏi heap
   ...
   write(out)            -> nén file tạm và phần còn lại thành .xlsx, ghi ra out
   close()               -> xoá file tạm
```

Giới hạn của SXSSF đến từ chính cửa sổ: không sửa được dòng đã ra file tạm, `autoSizeColumn` phải bật theo dõi trước (`trackAllColumnsForAutoSizing()`), công thức tham chiếu dòng cũ không được tính lại. Với báo cáo ghi một chiều từ trên xuống, đó không phải vấn đề. Một sheet Excel chứa tối đa 1.048.576 dòng, nên báo cáo lớn hơn phải chia sheet hoặc chuyển sang CSV.

Workbook nhỏ chưa đủ: dữ liệu đọc từ database cũng phải chảy theo luồng. pgJDBC mặc định đọc **toàn bộ** kết quả vào bộ nhớ; nó chỉ dùng cursor và lấy từng đợt khi **auto-commit tắt** (nằm trong transaction) và **fetch size lớn hơn 0**. Lab dùng `JdbcClient...withFetchSize(1000)` trong method `@Transactional(readOnly = true)`, xử lý từng dòng bằng `RowCallbackHandler` thay vì `.list()`.

**Stream response.** `StreamingResponseBody` cho controller trả về ngay, phần ghi byte chạy trên một thread của executor bất đồng bộ của Spring MVC và ghi thẳng vào socket. Ba hệ quả:

- Thời gian ghi tính vào **async request timeout**, mặc định của Tomcat là 30 giây; quá hạn client nhận `503`. Lab đặt `spring.mvc.async.request-timeout=2m`.
- Khi byte đầu tiên đã đi, status `200` đã gửi. Lỗi giữa chừng chỉ cắt cụt file, không đổi được thành `500`. Vì vậy lab dựng xong workbook rồi mới `write(out)`.
- Transaction mở trên thread ghi, không phải thread của request.

<Callout kind="production">

Một nút "Xuất Excel" dùng `XSSFWorkbook` chạy ổn nhiều tháng với dữ liệu nhỏ. Một ngày kế toán chọn "cả năm", heap đầy, GC chạy liên tục, mọi request khác trên instance đó chậm theo rồi lỗi. Bước 11 tái hiện chuyện này với heap 256 MB. Sửa tận gốc là SXSSF cộng giới hạn phạm vi xuất (khoảng ngày tối đa, số dòng tối đa); báo cáo thật lớn thì chạy nền và gửi link qua email (SB10.2). Còn việc để JVM thoát hẳn sau `OutOfMemoryError` cho orchestrator khởi động lại là cấu hình JVM của SB11.3.

</Callout>

### PDF: thư viện, giấy phép và font

| Thư viện | Giấy phép | Hợp với |
|---|---|---|
| iText 9 | AGPL hoặc thương mại | Đầy đủ tính năng; AGPL buộc công bố mã nguồn của cả dịch vụ dùng nó, nếu không thì mua giấy phép |
| **OpenPDF** 3 | LGPL 2.1 hoặc MPL 2.0 | Nhánh từ iText 4 trước khi đổi giấy phép; API `Document`, `PdfPTable`; dùng trong lab |
| Apache PDFBox | Apache 2.0 | Đọc, tách, ghép PDF; tạo PDF ở mức thấp (tự đặt toạ độ chữ) |
| OpenHTMLtoPDF, Flying Saucer | LGPL | Viết HTML/CSS (template Thymeleaf như SB10.2) rồi chuyển sang PDF |

Kiểm giấy phép trước khi thêm thư viện là việc của người viết code, không phải việc của phòng pháp chế sau khi sản phẩm đã bán. OpenPDF 3 đổi package từ `com.lowagie.text` sang `org.openpdf.text`; ví dụ trên mạng cho bản cũ không biên dịch được với bản mới.

**Font.** PDF có 14 font chuẩn (Helvetica, Times…) mà trình đọc nào cũng có, nhưng chúng chỉ mã hoá bảng ký tự Latin cơ bản (WinAnsi, CP1252). Chữ `đ`, `ạ`, `ễ` không có trong bảng đó, và OpenPDF **lặng lẽ bỏ** chúng: không exception, chỉ mất chữ. Muốn tiếng Việt, nhúng một font TrueType có đủ glyph với encoding `IDENTITY_H` (Unicode). Lab dùng Liberation Sans (giấy phép SIL OFL) có sẵn trong artifact `openpdf-fonts-extra`. Font thương mại như Arial có giấy phép riêng về việc nhúng vào file phát hành.

### Tên file tiếng Việt trong Content-Disposition

Header HTTP về nguyên tắc chỉ chứa ASCII. **RFC 6266** quy định `Content-Disposition`, và **RFC 5987** (nay là RFC 8187) thêm cú pháp `filename*` mang chuỗi UTF-8 đã percent-encode. Gửi cả hai: trình duyệt hiểu `filename*` dùng nó, công cụ cũ dùng `filename`:

```text
Content-Disposition: attachment; filename="Bao cao _on hang.xlsx";
                     filename*=UTF-8''B%C3%A1o%20c%C3%A1o%20%C4%91%C6%A1n%20h%C3%A0ng.xlsx
```

`ContentDisposition.attachment().filename(name, UTF_8)` của Spring sinh đúng dạng này: phần `filename` bỏ dấu, ký tự không quy được về ASCII như `đ` thành `_`. Đừng tự ghép chuỗi `"attachment; filename=\"" + name + "\""`: tên chứa dấu `"` hoặc xuống dòng sẽ phá header.

```bash
package vn.masteva.files;

import java.io.IOException;
import java.io.InputStream;
import java.net.URI;
import java.nio.charset.StandardCharsets;
import java.security.DigestInputStream;
import java.security.MessageDigest;
import java.security.NoSuchAlgorithmException;
import java.time.Duration;
import java.util.HexFormat;
import java.util.Set;
import java.util.UUID;
import org.apache.tika.Tika;
import org.springframework.http.ContentDisposition;
import org.springframework.http.HttpStatus;
import org.springframework.http.ProblemDetail;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Service;
import org.springframework.web.ErrorResponseException;
import org.springframework.web.multipart.MultipartFile;
import software.amazon.awssdk.core.sync.RequestBody;
import software.amazon.awssdk.services.s3.S3Client;
import software.amazon.awssdk.services.s3.presigner.S3Presigner;

@Service
public class FileService {
    private static final Set<String> ALLOWED = Set.of("image/png", "image/jpeg", "application/pdf");

    private final Tika tika = new Tika();
    private final S3Client s3;
    private final S3Presigner presigner;
    private final JdbcClient jdbc;
    private final String bucket;

    public FileService(S3Client s3, S3Presigner presigner, JdbcClient jdbc, StorageProperties props) {
        this.s3 = s3;
        this.presigner = presigner;
        this.jdbc = jdbc;
        this.bucket = props.bucket();
    }

    public StoredFile upload(MultipartFile file) throws IOException {
        String type;
        try (InputStream in = file.getInputStream()) {
            type = tika.detect(in);                       // đọc magic bytes, bỏ qua tên file
        }
        if (!ALLOWED.contains(type)) {
            throw new ErrorResponseException(HttpStatus.UNSUPPORTED_MEDIA_TYPE,
                    ProblemDetail.forStatusAndDetail(HttpStatus.UNSUPPORTED_MEDIA_TYPE,
                            "Nội dung file là " + type + ", chỉ nhận PNG, JPEG, PDF"), null);
        }
        UUID id = UUID.randomUUID();
        String key = "uploads/" + id;                     // không dùng tên người dùng gửi lên làm key
        MessageDigest sha256 = sha256();
        try (InputStream in = new DigestInputStream(file.getInputStream(), sha256)) {
            s3.putObject(b -> b.bucket(bucket).key(key).contentType(type),
                    RequestBody.fromInputStream(in, file.getSize()));
        }
        StoredFile stored = new StoredFile(id, file.getOriginalFilename(), type, file.getSize(),
                HexFormat.of().formatHex(sha256.digest()), key);
        jdbc.sql("""
                INSERT INTO stored_files (id, original_name, content_type, size_bytes, sha256, object_key)
                VALUES (:id, :originalName, :contentType, :sizeBytes, :sha256, :objectKey)
                """).paramSource(stored).update();
        return stored;
    }

    public URI downloadUrl(UUID id) {
        StoredFile f = jdbc.sql("SELECT * FROM stored_files WHERE id = ?").param(id)
                .query(StoredFile.class).optional()
                .orElseThrow(() -> new ErrorResponseException(HttpStatus.NOT_FOUND));
        String disposition = ContentDisposition.attachment()
                .filename(f.originalName(), StandardCharsets.UTF_8).build().toString();
        return URI.create(presigner.presignGetObject(r -> r
                .signatureDuration(Duration.ofMinutes(5))
                .getObjectRequest(g -> g.bucket(bucket).key(f.objectKey())
                        .responseContentDisposition(disposition)))
                .url().toString());
    }

    private static MessageDigest sha256() {
        try {
            return MessageDigest.getInstance("SHA-256");
        } catch (NoSuchAlgorithmException e) {
            throw new IllegalStateException(e);
        }
    }
}
EOF
```

- `S3Client` gọi mạng; `S3Presigner` chỉ tính chữ ký. Cả hai cùng endpoint ở lab; production có thể khác nhau (callout Trên production).
- `RequestBody.fromInputStream(in, size)` stream file lên storage, không đọc cả file vào `byte[]`. `DigestInputStream` tính SHA-256 trên đường đi; mã băm dùng để phát hiện file trùng hay file bị sửa.
- `ErrorResponseException` mang sẵn status và `ProblemDetail`; handler Problem Details của Spring Boot trả nó thành `application/problem+json`.
- `.paramSource(stored)` lấy tham số đặt tên từ các component của record.
- Lab không có đăng nhập, nên ai biết id cũng tải được. Trong ứng dụng thật, `downloadUrl` kiểm người đang gọi có quyền với file này không, trước khi ký (SB6.3 bàn lỗi IDOR).

```bash
            int[] next = {1};
            jdbc.sql("SELECT id, customer, status, total, created_at FROM orders ORDER BY id")
                    .withFetchSize(1000)
                    .query(rs -> {
                        Row row = sheet.createRow(next[0]++);
                        row.createCell(0).setCellValue(rs.getLong("id"));
                        row.createCell(1).setCellValue(rs.getString("customer"));
                        row.createCell(2).setCellValue(rs.getString("status"));
                        row.createCell(3).setCellValue(rs.getLong("total"));
                        var created = row.createCell(4);
                        created.setCellValue(rs.getObject("created_at", OffsetDateTime.class)
                                .atZoneSameInstant(VN).toLocalDateTime());
                        created.setCellStyle(dateStyle);
                    });
            log.info(">> {}: {} dòng, heap sau GC: {} MB", engine, next[0] - 1, usedHeapAfterGcMb());
            wb.write(out);
        }
    }

    // Chỉ để đo trong lab: ép GC rồi đọc heap đang dùng.
    private static long usedHeapAfterGcMb() {
        System.gc();
        return ManagementFactory.getMemoryMXBean().getHeapMemoryUsage().getUsed() / (1024 * 1024);
    }

package vn.masteva.files;

import java.io.IOException;
import java.io.OutputStream;
import java.time.OffsetDateTime;
import java.time.ZoneId;
import java.time.format.DateTimeFormatter;
import org.openpdf.text.Document;
import org.openpdf.text.Font;
import org.openpdf.text.PageSize;
import org.openpdf.text.Paragraph;
import org.openpdf.text.Phrase;
import org.openpdf.text.pdf.BaseFont;
import org.openpdf.text.pdf.PdfPTable;
import org.openpdf.text.pdf.PdfWriter;
import org.springframework.jdbc.core.simple.JdbcClient;
import org.springframework.stereotype.Service;
import org.springframework.transaction.annotation.Transactional;

@Service
public class PdfReport {
    private static final DateTimeFormatter TIME =
            DateTimeFormatter.ofPattern("dd/MM/yyyy HH:mm").withZone(ZoneId.of("Asia/Ho_Chi_Minh"));

    private final JdbcClient jdbc;

    public PdfReport(JdbcClient jdbc) {
        this.jdbc = jdbc;
    }

    @Transactional(readOnly = true)
    public void orders(String font, int limit, OutputStream out) throws IOException {
        BaseFont base = "builtin".equals(font)
                ? BaseFont.createFont(BaseFont.HELVETICA, BaseFont.CP1252, BaseFont.NOT_EMBEDDED)
                : BaseFont.createFont("liberation/LiberationSans-Regular.ttf", BaseFont.IDENTITY_H, BaseFont.EMBEDDED);
        Font text = new Font(base, 10);
        try (Document doc = new Document(PageSize.A4)) {
            PdfWriter.getInstance(doc, out);
            doc.open();
            doc.add(new Paragraph("Báo cáo đơn hàng của Nguyễn Văn An", new Font(base, 14)));
            PdfPTable table = new PdfPTable(new float[] {1, 3, 2, 2, 3});
            table.setWidthPercentage(100);
            table.setHeaderRows(1);
            for (String h : new String[] {"Mã", "Khách hàng", "Trạng thái", "Tổng tiền", "Thời điểm"}) {
                table.addCell(new Phrase(h, text));
            }
            jdbc.sql("SELECT id, customer, status, total, created_at FROM orders ORDER BY id LIMIT :limit")
                    .param("limit", limit)
                    .query(rs -> {
                        table.addCell(new Phrase(String.valueOf(rs.getLong("id")), text));
                        table.addCell(new Phrase(rs.getString("customer"), text));
                        table.addCell(new Phrase(rs.getString("status"), text));
                        table.addCell(new Phrase("%,d".formatted(rs.getLong("total")), text));
                        table.addCell(new Phrase(TIME.format(rs.getObject("created_at", OffsetDateTime.class)), text));
                    });
            doc.add(table);
        }
    }
}

package vn.masteva.files;

import jakarta.validation.constraints.Max;
import java.io.IOException;
import java.nio.charset.StandardCharsets;
import java.util.UUID;
import org.springframework.http.ContentDisposition;
import org.springframework.http.HttpHeaders;

import org.springframework.http.ResponseEntity;
import org.springframework.web.bind.annotation.GetMapping;

import org.springframework.web.bind.annotation.RestController;

    @GetMapping("/reports/orders.pdf")

    }
```

### Khi gặp lỗi

<Callout kind="pitfall">

- `pull access denied for minio/minio`: ví dụ cũ dùng MinIO; image cộng đồng không còn, dùng RustFS như bước 1.
- `S3Exception: The specified bucket does not exist`: chưa chạy `s3cli s3 mb` ở bước 1, hoặc tên bucket trong `storage.bucket` khác.
- `s3cli` báo `Could not connect to the endpoint URL`: RustFS chưa chạy, hoặc Docker của bạn không có `host.docker.internal` (Docker trên Linux cần thêm `--add-host=host.docker.internal:host-gateway`).
- PutObject bị từ chối với lỗi về checksum ở một dịch vụ tương thích S3 khác: từ khoảng bản 2.30, AWS SDK v2 mặc định tính và gửi checksum cho mọi request; dịch vụ chưa hỗ trợ thì đặt `requestChecksumCalculation(RequestChecksumCalculation.WHEN_REQUIRED)` khi dựng `S3Client`.
- `SignatureDoesNotMatch` khi tải bằng URL chưa sửa gì: endpoint của `S3Presigner` khác host mà trình duyệt gọi, hoặc một proxy ở giữa đổi header `Host`.
- Excel nhận `503` sau đúng 30 giây: thiếu `spring.mvc.async.request-timeout`.
- PDF báo không tìm thấy `liberation/LiberationSans-Regular.ttf`: thiếu dependency `openpdf-fonts-extra`.

</Callout>

<Reveal title="Trình duyệt tải thẳng file lên storage bằng presigned PUT. Làm sao vẫn chặn file quá lớn và file sai loại?">

Presigned PUT ký phương thức, bucket, key và hạn; nếu không ký thêm header thì client gửi bao nhiêu byte cũng được. Có ba lớp kiểm tra. Lúc ký: ký kèm `Content-Length` và `Content-Type` mà client khai, để storage từ chối body khác cỡ; hoặc dùng presigned POST với policy `content-length-range`. Sau khi tải: client gọi API "xác nhận" của ứng dụng; ứng dụng `HeadObject` để biết kích thước thật, đọc vài KB đầu bằng `GetObject` có `Range` để kiểm magic bytes, rồi mới ghi metadata. Đặt object mới vào tiền tố `incoming/` có lifecycle rule tự xoá sau một ngày, và chỉ chuyển sang `uploads/` khi đã xác nhận. Cách này đổi sự đơn giản của bước 7 lấy việc file lớn không chiếm thread và băng thông của ứng dụng.

</Reveal>

<Reveal title="Người dùng cần báo cáo 2 triệu dòng. Tăng heap có phải cách?">

Không. Excel chỉ chứa 1.048.576 dòng mỗi sheet, và một request HTTP chạy nhiều phút sẽ đụng timeout của proxy, load balancer và trình duyệt. Cách bền vững: request chỉ tạo một job (bảng `report_jobs` hoặc Spring Batch như SB9.4), job ghi file vào object storage bằng SXSSF hoặc CSV, xong thì gửi email chứa presigned URL (SB10.2). Thêm giới hạn số job đồng thời cho mỗi người để một người bấm mười lần không làm nghẽn cả hệ thống.

</Reveal>

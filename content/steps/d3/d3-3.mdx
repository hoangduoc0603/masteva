<Goal>

Biết lúc nào nên dừng viết Bash, và viết được công cụ vận hành nhỏ bằng một ngôn ngữ lập trình mà vẫn giữ các quy ước của dòng lệnh Unix. Học xong bài này, bạn giải thích được:

- Lỗi nào nên thử lại, lỗi nào không, và vì sao thử lại phải có khoảng chờ tăng dần.

### Khi Bash không còn hợp: Python, hoặc Go

Bài D3.2 cho thấy ghép `grep | awk | sort` và `jq` trả lời được rất nhiều câu hỏi. Nó bắt đầu vỡ khi bạn cần: cấu trúc dữ liệu lồng nhau, phép tính như percentile, xử lý từng loại lỗi khác nhau, thử lại có chờ, gọi API, hoặc kiểm thử tự động. Lúc đó chuyển sang một ngôn ngữ lập trình. Python có sẵn trên mọi máy Ubuntu và thư viện chuẩn của nó đủ cho hầu hết việc vận hành, không cần cài gì thêm:

| Module | Dùng cho |
|---|---|
| `argparse` | Tham số dòng lệnh, có `--help` tự sinh |
| `json`, `csv` | Đọc ghi dữ liệu có cấu trúc |
| `subprocess` | Chạy lệnh ngoài và lấy exit code, output |
| `pathlib`, `shutil`, `tempfile` | File và thư mục |
| `urllib.request` | Gọi HTTP (đủ cho health check; API phức tạp thì dùng thư viện ngoài) |
| `statistics`, `collections` | Trung vị, percentile, đếm, gom nhóm |
| `logging` | Log có mức độ, ra stderr |
| `concurrent.futures` | Chạy song song có giới hạn |

Ba quy tắc khi gọi lệnh ngoài bằng `subprocess.run`:

1. Truyền **danh sách** tham số (`["systemctl", "is-active", unit]`), không dùng `shell=True` với chuỗi ghép từ đầu vào. Không có shell thì không có word splitting, glob hay chèn lệnh.
2. Luôn đặt `timeout`. Một lệnh treo không được làm treo công cụ của bạn.
3. Quyết định rõ về exit code: `check=True` để lỗi thành exception, hoặc `check=False` rồi tự đọc `returncode` khi mã khác 0 là kết quả hợp lệ.

Và script Python cũng phải giữ quy ước Unix của D3.1: dữ liệu ra stdout, thông báo ra stderr, exit code có nghĩa.

### 1. Python: báo cáo có percentile và ngưỡng cảnh báo

Bảng tổng hợp bằng awk ở bước 4 của D3.2 dừng ở trung bình. Việc mà awk bắt đầu đuối: percentile theo từng đường dẫn, bỏ qua dòng hỏng mà không chết, xuất bảng hoặc JSON, và trả exit code khi vượt ngưỡng lỗi.

<Terminal where="vm" title="~/masteva-d3/logreport.py">

```bash
cat > logreport.py <<'EOF'
#!/usr/bin/env python3
"""Báo cáo theo đường dẫn từ access log dạng JSON của Nginx.

Thoát mã 1 khi có đường dẫn vượt ngưỡng lỗi, để dùng trong cron hoặc CI.
"""
import argparse
import json
import statistics
import sys
from collections import defaultdict

def load(path):
    """Trả về (danh sách bản ghi, số dòng hỏng). Dòng hỏng được đếm, không làm dừng."""
    records, bad = [], 0
    with open(path, encoding="utf-8") as f:
        for line in f:
            try:
                rec = json.loads(line)
                records.append((rec["path"], int(rec["status"]), float(rec["rt"])))
            except (json.JSONDecodeError, KeyError, TypeError, ValueError):
                bad += 1
    return records, bad

def summarize(records):
    by_path = defaultdict(list)
    for path, status, rt in records:
        by_path[path].append((status, rt))
    rows = []
    for path, items in by_path.items():
        times = sorted(rt for _, rt in items)
        errors = sum(1 for status, _ in items if status >= 500)
        p95 = statistics.quantiles(times, n=100, method="inclusive")[94] if len(times) > 1 else times[0]
        rows.append({
            "path": path,
            "req": len(items),
            "err_pct": round(errors / len(items) * 100, 1),
            "p50_ms": round(statistics.median(times) * 1000),
            "p95_ms": round(p95 * 1000),
        })
    return sorted(rows, key=lambda r: -r["req"])

def main():
    parser = argparse.ArgumentParser(description=__doc__.splitlines()[0])
    parser.add_argument("logfile")
    parser.add_argument("--max-error-pct", type=float, default=5.0)
    parser.add_argument("--json", action="store_true", help="in JSON thay cho bảng")
    args = parser.parse_args()

    try:
        records, bad = load(args.logfile)
    except OSError as e:
        print(f"LỖI: không đọc được {args.logfile}: {e.strerror}", file=sys.stderr)
        return 2
    if bad:
        print(f"cảnh báo: bỏ qua {bad} dòng không đọc được", file=sys.stderr)

    rows = summarize(records)
    if args.json:
        json.dump(rows, sys.stdout, ensure_ascii=False, indent=2)
        print()
    else:
        print(f"{'path':<18} {'req':>5} {'err%':>6} {'p50_ms':>7} {'p95_ms':>7}")
        for r in rows:
            print(f"{r['path']:<18} {r['req']:>5} {r['err_pct']:>6} {r['p50_ms']:>7} {r['p95_ms']:>7}")

    over = [r["path"] for r in rows if r["err_pct"] > args.max_error_pct]
    if over:
        print(f"VƯỢT NGƯỠNG {args.max_error_pct}% lỗi: {', '.join(over)}", file=sys.stderr)
        return 1
    return 0

if __name__ == "__main__":
    sys.exit(main())
EOF
```

### 2. Python: gọi lệnh ngoài và thử lại

Script thứ hai kiểm tra unit systemd (qua `subprocess`) và URL (qua `urllib`), thử lại khi lỗi có thể là tạm thời:

<Terminal where="vm" title="~/masteva-d3/svccheck.py">

```bash
cat > svccheck.py <<'EOF'
#!/usr/bin/env python3
"""Kiểm tra unit systemd và URL, thử lại khi lỗi tạm thời, in báo cáo JSON."""
import json
import subprocess
import sys
import time
import urllib.error
import urllib.request

def unit_active(unit):
    """systemctl is-active trả 0 khi unit đang chạy, khác 0 khi không."""
    try:
        result = subprocess.run(
            ["systemctl", "is-active", unit],      # danh sách tham số, không qua shell
            capture_output=True, text=True, timeout=5, check=False,
        )
    except FileNotFoundError:
        return {"unit": unit, "ok": False, "detail": "không có systemctl"}
    except subprocess.TimeoutExpired:
        return {"unit": unit, "ok": False, "detail": "quá 5 giây"}
    return {"unit": unit, "ok": result.returncode == 0, "detail": result.stdout.strip()}

def url_ok(url, attempts=3, timeout=2.0):
    """Coi 2xx là tốt. Thử lại với lỗi mạng và 5xx, không thử lại với 4xx."""
    detail = ""
    for attempt in range(1, attempts + 1):
        try:
            with urllib.request.urlopen(url, timeout=timeout) as resp:
                return {"url": url, "ok": True, "detail": f"HTTP {resp.status}", "attempts": attempt}
        except urllib.error.HTTPError as e:
            detail = f"HTTP {e.code}"
            if e.code < 500:
                break
        except (urllib.error.URLError, TimeoutError) as e:
            detail = str(getattr(e, "reason", e))
        if attempt < attempts:
            time.sleep(0.2 * 2 ** (attempt - 1))   # 0,2 s rồi 0,4 s
    return {"url": url, "ok": False, "detail": detail, "attempts": attempt}

def main(argv):
    checks = [unit_active(a) if not a.startswith("http") else url_ok(a) for a in argv]
    json.dump(checks, sys.stdout, ensure_ascii=False, indent=2)
    print()
    return 0 if all(c["ok"] for c in checks) else 1

if __name__ == "__main__":
    sys.exit(main(sys.argv[1:]))
EOF
python3 svccheck.py nginx http://127.0.0.1:8088/health | jq -c '.[]'; echo "exit=${PIPESTATUS[0]}"
python3 svccheck.py khong-co.service http://127.0.0.1:8088/admin/x http://127.0.0.1:9/ | jq -c '.[]'; echo "exit=${PIPESTATUS[0]}"
```

</Terminal>

- `systemctl is-active` trả mã khác 0 cho unit không chạy; đó là **câu trả lời**, không phải sự cố, nên `check=False` và đọc `returncode`. Lỗi thật của việc chạy lệnh (không có `systemctl`, lệnh treo) là exception riêng.

- `Connection refused` chính là kiểu lỗi thứ nhất của D2.1: không có gì nghe ở port 9.

Thử lại chỉ an toàn với thao tác đọc hoặc thao tác idempotent; thử lại một lệnh thanh toán không có idempotency key là trừ tiền hai lần (J10.2 dạy idempotency key).

### 3. Cùng một hàm, viết bằng Go

Hàm `unit_active` của `svccheck.py`, viết lại bằng Go: chạy `systemctl is-active` với timeout, phân biệt ba kiểu kết quả, in JSON và trả exit code. Viết và build trên máy Mac, rồi chép file binary vào VM.

```bash
// unitcheck: bản Go của hàm unit_active trong svccheck.py.
// Cách chạy: unitcheck <unit> [unit...]. Thoát mã 1 khi có unit không chạy.
package main

import (
	"context"
	"encoding/json"
	"errors"
	"os"
	"os/exec"
	"strings"
	"time"
)

type result struct {
	Unit   string `json:"unit"`
	OK     bool   `json:"ok"`
	Detail string `json:"detail"`
}

func unitActive(unit string) result {
	ctx, cancel := context.WithTimeout(context.Background(), 5*time.Second)
	defer cancel()

	// Tham số là một slice, không qua shell, như danh sách của subprocess.run
	out, err := exec.CommandContext(ctx, "systemctl", "is-active", unit).Output()
	detail := strings.TrimSpace(string(out))

	var exitErr *exec.ExitError
	switch {
	case err == nil:
		return result{unit, true, detail}
	case errors.Is(ctx.Err(), context.DeadlineExceeded):
		return result{unit, false, "quá 5 giây"}
	case errors.As(err, &exitErr):
		return result{unit, false, detail} // systemctl chạy được, trả mã khác 0
	default:
		return result{unit, false, err.Error()} // không chạy được systemctl
	}
}

func main() {
	results := []result{}
	failed := false
	for _, unit := range os.Args[1:] {
		r := unitActive(unit)
		results = append(results, r)
		failed = failed || !r.OK
	}
	enc := json.NewEncoder(os.Stdout)
	enc.SetIndent("", "  ")
	_ = enc.Encode(results)
	if failed {
		os.Exit(1)
	}
}
```

|---|---|---|

<Reveal title="Có nên dùng shell=True cho tiện?">

`subprocess.run(f"grep {pattern} {path}", shell=True)` chạy chuỗi đó qua `/bin/sh`. Nếu `pattern` đến từ người dùng và chứa `; rm -rf ~`, shell sẽ chạy nó: đó là lỗ hổng chèn lệnh. Mọi vấn đề word splitting và glob của D3.1 cũng quay lại. Với danh sách tham số, mỗi phần tử tới chương trình đúng như một tham số, không qua shell. Khi thật sự cần pipe giữa hai chương trình, nối chúng bằng Python (`stdout=subprocess.PIPE` của tiến trình này làm `stdin` của tiến trình kia), hoặc làm phần lọc ngay trong Python.

</Reveal>

<Reveal title="Khi nào viết lại công cụ Python bằng Go?">

Khi việc phát hành trở thành vấn đề lớn hơn việc viết: công cụ phải chạy trên hàng trăm máy với phiên bản Python khác nhau, trong container tối giản không có trình thông dịch, hoặc trên máy của khách hàng. Một binary Go tĩnh giải quyết gọn. Lý do thứ hai là chạy song song thật sự (kiểm tra hàng nghìn endpoint cùng lúc) và lý do thứ ba là tích hợp với hệ sinh thái Kubernetes: client-go, controller-runtime (K9). Ngược lại, script 80 dòng chạy trên vài máy bạn quản lý thì giữ Python.

</Reveal>

<Reveal title="Script cần một thư viện ngoài (requests, boto3, PyYAML). Cài thế nào trên máy chủ?">

Đừng `pip install` vào Python của hệ thống. Trên Ubuntu 26.04, Python hệ thống được đánh dấu "externally managed" (file `/usr/lib/python3.14/EXTERNALLY-MANAGED`), để `pip` không ghi đè các gói mà công cụ của hệ điều hành cần; VM của lab thậm chí không cài sẵn `pip`. Ba cách đúng, theo thứ tự nên thử: dùng gói của distro (`apt install python3-requests`), ổn định và được vá cùng hệ thống; tạo môi trường ảo cho công cụ (`python3 -m venv`, hoặc `pipx` cho công cụ dòng lệnh), cô lập khỏi hệ thống; hoặc đóng gói công cụ thành image container. Mỗi thư viện ngoài là một thứ phải cài và vá trên mọi máy chạy script, nên với script vận hành, thư viện chuẩn là lựa chọn đầu tiên. Đây cũng là chỗ Go thắng rõ: phụ thuộc được biên dịch vào trong binary.

</Reveal>

<Reveal title="Kiểm thử một script vận hành như thế nào?">

Tách phần **tính toán** khỏi phần **tác động ra ngoài**. Trong `logreport.py`, `summarize()` nhận danh sách và trả danh sách, không đọc file, không in gì: viết test cho nó bằng `unittest` hay `pytest` chỉ mất vài dòng, với dữ liệu bạn tự đếm được kết quả. Phần gọi lệnh ngoài và HTTP thì kiểm theo hai lớp: thay `subprocess.run` hoặc `urlopen` bằng bản giả để thử từng nhánh lỗi (timeout, mã khác 0, không tìm thấy lệnh), và chạy thật trên môi trường lab như bài này đã làm với Nginx và backend giả. Thêm một cờ `--dry-run` in ra việc sẽ làm mà không làm, cho mọi công cụ có thao tác thay đổi hệ thống. Go có sẵn `go test`; cùng nguyên tắc tách hàm.

</Reveal>

<Callout kind="ai">

Nhờ AI viết khung một công cụ Python (argparse, đọc file, in bảng) hoặc chuyển một script Bash dài sang Python: nhanh và thường đúng cấu trúc. Lỗi hay gặp ở bản AI viết: `shell=True` với chuỗi ghép, `except Exception: pass` nuốt mọi lỗi, không có `timeout`, thử lại vô hạn không chờ, in thông báo lỗi ra stdout, và `import` thư viện ngoài cho việc mà thư viện chuẩn làm được. Với Go, AI hay bỏ qua `err` bằng `_` và quên huỷ context. Kiểm bằng cách chạy từng nhánh lỗi như bước 1 và 2 (file hỏng, file thiếu, port đóng, unit không tồn tại) và nhìn exit code; với Go thêm `go vet`.
